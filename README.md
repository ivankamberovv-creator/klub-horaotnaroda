# Клуб „Хора от Народа“

Приложение за телефон за клиентите на магазините „Хора от Народа“: личен код за касата, точки от всяка покупка, промоции, които клиентът сам си активира, награди срещу точки и история на покупките.

Това е **отделен проект на отделен сървър**. Няма общо със сайта horaotnaroda.bg, с неговото хранилище и с неговия сървър.

## Какво има тук

| Папка | Какво е |
| --- | --- |
| `server/` | Сървърът: клиенти, вход с телефон, точки, промоции, награди, покупки. Node 22+, Fastify, SQLite. |
| `server/public/admin/` | Страницата за служители: „Каса“ (за касиерите) и управление (промоции, награди, клиенти). |
| `app/` | Приложението за телефон: Expo (React Native), за Android и iPhone. |
| `docs/belezhki.md` | Идеята, решенията и отворените въпроси към Янак Софт. |
| `deploy/` | Примерна systemd услуга за сървъра. |
| `tools/e2e.cjs` | Проверка на целия поток от край до край. |

## Докъде е стигнато

Работи като **демо**: всичко по-долу е пробвано, но без истински SMS и без връзка с касовата програма.

- Вход с телефон и 6-цифрен код; при първо влизане се пита името.
- Всеки клиент получава свой код (баркод EAN-13), който касата сканира.
- Покупка носи точки; активираните промоции ги умножават или добавят точки отгоре.
- Точките се разменят за награди; касата издава наградата или я отказва (тогава точките се връщат).
- Клиентът вижда покупките си: магазин, сума, отстъпка, точки, артикули.
- Управление: промоции, награди, списък с клиенти и обобщение.
- Клиентът може сам да изтрие профила си.

Какво **липсва** до истинско пускане:

1. **Връзка с касовата програма „ЯНАК“.** Има само заготовка (`server/src/connectors/yanak.js`). Трябва достъп от Янак Софт и примерен отговор на справките им. Докато няма, покупките се въвеждат на ръка от страницата „Каса“.
2. **Отстъпките на касата.** Сървърът знае коя промоция е активирал клиентът, но самата отстъпка в бона я прави касовата програма. Как ЯНАК ще научи за активираната промоция, още не е решено.
3. **Доставчик на SMS** за кода за вход. Засега кодът само се печата (демо).
4. **Издаване в магазините за приложения**: профили в Apple и Google, иконка с високо качество (сегашната е от шаблона), политика за поверителност, EAS build.
5. **Сървър** за клуба с домейн и HTTPS.

## Как да го пуснете при себе си

Нужен е Node 22 или по-нов.

### Сървърът

```
cd server
npm install
npm run demo
```

Сървърът тръгва на http://localhost:4100 с примерни промоции и награди. Страницата за служители е на http://localhost:4100/admin/. В демото паролата за управление е `demo-admin`, а ПИН-ът на касата е `1234`. Извън демото и двете се задават с настройки и сървърът не тръгва със слаби.

### Приложението

```
cd app
npm install
EXPO_PUBLIC_API_URL=http://АДРЕС-НА-КОМПЮТЪРА:4100 npx expo start
```

Отваря се с Expo Go на телефона (или в емулатор). Телефонът трябва да стига до сървъра: пуснете сървъра с `HOST=0.0.0.0 npm run demo` и сложете в адреса IP-то на компютъра в локалната мрежа. В демото кодът за вход се показва на екрана, защото SMS не се праща.

В браузър, за бърз преглед: `EXPO_PUBLIC_API_URL=http://localhost:4100 npx expo start --web`.

## Как работи

- **Код на клиента.** EAN-13 с префикс 29 (баркодове за вътрешна употреба) и 10 случайни цифри, за да не може да се отгатне чужд код. Четецът на касата го чете като обикновен баркод.
- **Точки.** `POINTS_PER_EURO` точки за всяко цяло евро от платената сума. Записват се в книга (`points_ledger`); салдото е сборът.
- **Промоции.** Четири вида: отстъпка в % (прилага я касата), точки по няколко (множител), точки отгоре при покупка над дадена сума и съобщение. Важат само активираните от клиента и само в срока си.
- **Награди.** При размяна точките се взимат веднага, а наградата чака на касата. Касиерът я издава или отказва.
- **Покупки.** Идват от касата през сменяем модул (`server/src/connectors/`). Един и същ документ не носи точки два пъти.
- **Роли.** Клиент (приложението), каса (ПИН: търсене по код, издаване на награди, пробни покупки в демото) и управление (парола: всичко).

## Настройки на сървъра

Всички са променливи на средата; примерен файл: `server/.env.example`.

| Име | По подразбиране | За какво е |
| --- | --- | --- |
| `DEMO` | няма | `1` пуска демото: примерни данни, кодът за вход се връща в отговора |
| `PORT`, `HOST` | `4100`, `127.0.0.1` | къде слуша сървърът |
| `DB_PATH` | `./data/klub.db` | файлът с базата данни |
| `ADMIN_PASSWORD` | няма | парола за управлението, поне 12 знака |
| `KASA_PIN` | няма | ПИН за касите, поне 6 знака |
| `POINTS_PER_EURO` | `1` | точки за всяко цяло евро |
| `CARD_PREFIX` | `29` | първите две цифри на кода на клиента (20–29) |
| `KASA` | `demo` | `demo` или `yanak` |
| `SMS_PROVIDER` | `demo` | доставчик на SMS; засега има само демо |
| `CORS_ORIGIN` | няма | само ако приложението се пуска в браузър |
| `TRUST_PROXY` | няма | `1`, когато сървърът е зад nginx |

## Проверки

```
cd server && npm test          # логиката и пътищата на сървъра
cd app && npm test             # баркодът
cd app && npm run typecheck    # типовете на приложението
```

### Проверка от край до край

Минава през целия поток: вход, активиране на промоция, покупка на касата, точки, награда, издаване, история, управление. Нужен е Playwright.

```
cd server && rm -f data/demo.db* && npm run demo                                  # чиста демо база
cd app && EXPO_PUBLIC_API_URL=http://localhost:4100 npx expo export --platform web
npx serve app/dist -l 8082                                                        # или друг статичен сървър на порт 8082
node tools/e2e.cjs /папка/за/снимките
```

## Сървърът за клуба

Сървърът на клуба е отделна машина. Примерна услуга има в `deploy/klub.service`: базата стои в `/var/lib/klub`, настройките в `/etc/klub/klub.env`. Пред него се слага nginx с HTTPS, а приложението се строи с адреса му в `EXPO_PUBLIC_API_URL`.
