# Клуб „Хора от Народа“

Приложение за клиентите на магазините „Хора от Народа“: карта за касата, точки от всяка покупка, оферти, които клиентът сам си активира, награди срещу точки, история на покупките, магазини и новини.

Това е **отделен проект на отделен сървър**. Няма общо със сайта horaotnaroda.bg, с неговото хранилище и с неговия сървър.

Приложението **не минава през магазините за приложения**. Отваря се от сайта на клуба и се слага на началния екран на телефона; оттам работи като всяко друго приложение, а картата се вижда и без интернет.

## Какво има тук

| Папка | Какво е |
| --- | --- |
| `server/` | Сървърът: клиенти, вход с телефон, точки, оферти, награди, покупки, магазини, новини. Node 22.13+, Fastify, вграденият SQLite. Той сервира и самото приложение. |
| `server/public/admin/` | Страницата за служители: „Каса“ (за касиерите) и управление (оферти, награди, магазини, новини, клиенти). |
| `app/` | Приложението: Expo (React Native). Строи се за браузър и се сервира от сървъра на клуба. |
| `tools/build-web.mjs` | Строи приложението за сайта на клуба (`app/dist`), с работа без интернет. |
| `tools/e2e.cjs` | Проверка на целия поток от край до край. |
| `docs/belezhki.md` | Идеята, решенията, какво имат големите приложения и отворените въпроси. |
| `deploy/` | Примерна systemd услуга за сървъра. |

## Какво прави приложението

Подредбата следва големите приложения с карти за лоялност (Lidl Plus, Kaufland, BILLA): картата е в средата и се отваря с едно докосване.

| Раздел | Какво има |
| --- | --- |
| Начало | Точките и колко остава до следващата награда, бутон към картата, офертите, последната покупка, новините |
| Оферти | Оферти със снимки, активиране и отказ, „Всички“ и „Активирани“, колко дни остават |
| Карта | Баркод EAN-13 за касата. Вижда се и без интернет |
| Награди | Размяна на точки за награди; какво чака на касата |
| Още → Талони за изтриване | След по-голяма покупка идва талон; трие се с пръст и носи точки |
| Още → Мисии | Задачи със срок („три покупки този месец“) с лента за напредъка и точки за изпълнение |
| Още → Моите покупки | Всяка покупка: магазин, сума, отстъпка, точки, артикули |
| Още → История на точките | Всяко начисляване и всяко харчене |
| Още → Магазини | Търсене, работно време, „отворено сега“, обаждане, упътване, любим магазин |
| Още → Новини | Новини със снимки; знак за непрочетени |
| Още → Профил | Име, рожден ден (записва се веднъж), изход, изтриване на профила |

Сървърът и управлението:

- Вход с телефон и 6-цифрен код.
- Точки за всяко цяло евро; оферти, които ги умножават или добавят точки отгоре.
- Точки подарък при регистрация и на рождения ден (по желание; `WELCOME_POINTS`, `BIRTHDAY_POINTS`).
- Талони за изтриване след покупка (по желание; `SCRATCH_MIN_EURO`, `SCRATCH_PRIZES`) и мисии, които се задават от управлението.
- Когато точките се увеличат, приложението празнува: числото „брои“ нагоре, излиза „+N точки“ и падат конфети. Който е изключил анимациите на телефона си, не ги вижда.
- Касата намира клиента по кода, издава награди и (в демото) записва пробни покупки.
- Управлението поддържа офертите, наградите, мисиите, магазините и новините, със снимки.

## Какво липсва до истинско пускане

1. **Връзка с касовата програма „ЯНАК“.** Има само заготовка (`server/src/connectors/yanak.js`). Трябва достъп от Янак Софт и примерен отговор на справките им. Докато няма, покупките се въвеждат на ръка от страницата „Каса“.
2. **Отстъпките на касата.** Сървърът знае коя оферта е активирал клиентът, но самата отстъпка в бона я прави касовата програма. Как ЯНАК ще научава за активираната оферта, още не е решено.
3. **Доставчик на SMS** за кода за вход. Засега кодът само се печата (демо).
4. **Сървър** за клуба с домейн и HTTPS. Без HTTPS телефоните не позволяват слагане на началния екран и работа без интернет.
5. **Иконка с високо качество.** Сегашните са от логото в 320 пиксела и на голям екран са леко размазани.
6. **Политика за поверителност**: приложението пази телефон, име, рожден ден и покупки.

Какво имат големите приложения, а тук още няма: седмична брошура, списък за пазаруване, известия на заключен екран, оферти от партньори. Вижте `docs/belezhki.md`.

## Как да го пуснете при себе си

Нужен е Node 22.13 или по-нов. Базата данни е вграденият в Node SQLite, така че при инсталиране няма нищо за компилиране.

```
npm run setup      # инсталира нужното за сървъра и за приложението (веднъж)
npm run build      # строи приложението в app/dist
npm run demo       # пуска сървъра с примерни данни
```

Командите са едни и същи на Windows, macOS и Linux и се пускат от главната папка на проекта.

- Приложението: http://localhost:4100
- Страницата за служители: http://localhost:4100/admin/ (в демото паролата за управление е `demo-admin`, ПИН-ът на касата е `1234`)

В демото кодът за вход се показва на екрана, защото SMS не се праща. Има примерни оферти, награди и една новина; магазините са списъкът към 15.11.2026 и после се поддържат от управлението.

За да го отворите от телефон в същата мрежа: `npm run demo:lan`; сървърът изписва адреса, който да отворите на телефона (компютърът и телефонът трябва да са на един Wi-Fi, а защитната стена на компютъра да пуска порт 4100). Слагането на началния екран и работата без интернет искат HTTPS, затова на телефон се виждат чак на истинския сървър.

Докато се работи по приложението: `cd app && EXPO_PUBLIC_API_URL=http://localhost:4100 npx expo start --web`.

## Как се слага на телефона

- **Android (Chrome):** при отваряне на сайта на клуба началният екран на приложението показва „Сложете приложението на началния екран“ с бутон „Инсталирайте“.
- **iPhone (Safari):** бутонът „Споделяне“, после „Към началния екран“. Apple не позволява бутон за това, затова приложението показва указанията.

Същият код може да се построи и като истинско приложение за Android (файл .apk, който се сваля от сайта) с инструментите на Expo. Това не е направено. За iPhone приложение извън App Store не е възможно за малък издател.

## Как работи

- **Код на клиента.** EAN-13 с префикс 29 (баркодове за вътрешна употреба) и 10 случайни цифри, за да не може да се отгатне чужд код.
- **Точки.** `POINTS_PER_EURO` точки за всяко цяло евро от платената сума. Записват се в книга (`points_ledger`); салдото е сборът.
- **Оферти.** Четири вида: отстъпка в % (прилага я касата), точки по няколко (множител), точки отгоре при покупка над дадена сума и съобщение. Важат само активираните от клиента и само в срока си.
- **Награди.** При размяна точките се взимат веднага, а наградата чака на касата. Касиерът я издава или отказва; при отказ точките се връщат.
- **Талони за изтриване.** Всеки талон печели; колко точно, се тегли на сървъра още при покупката според зададените тежести, а клиентът го вижда чак като изтрие талона. Точките се начисляват веднъж.
- **Мисии.** Два вида: брой покупки или обща сума в даден срок. Броят се само покупките с картата. Точките идват сами с покупката, която завършва мисията, и то веднъж.
- **Рожден ден.** Пита се само ден и месец и се записва веднъж. Точките идват на самия ден, ако рожденият ден е записан поне 30 дни по-рано.
- **Покупки.** Идват от касата през сменяем модул (`server/src/connectors/`). Един и същ документ не носи точки два пъти.
- **Снимки.** Качват се от управлението (JPEG, PNG или WebP до 2 MB) и стоят във файлове до базата.
- **Без интернет.** Файловете на приложението и последно видяният профил се пазят на телефона. Данните от сървъра (`/api/`) не се пазят.
- **Роли.** Клиент (приложението), каса (ПИН) и управление (парола).

## Настройки на сървъра

Всички са променливи на средата; примерен файл: `server/.env.example`.

| Име | По подразбиране | За какво е |
| --- | --- | --- |
| `DEMO` | няма | `1` пуска демото: примерни данни, кодът за вход се връща в отговора |
| `PORT`, `HOST` | `4100`, `127.0.0.1` | къде слуша сървърът |
| `DB_PATH` | `./data/klub.db` | файлът с базата данни |
| `UPLOAD_DIR` | `uploads` до базата | качените снимки |
| `APP_DIR` | `../app/dist` | готовото приложение, което се сервира на „/“ |
| `ADMIN_PASSWORD` | няма | парола за управлението, поне 12 знака |
| `KASA_PIN` | няма | ПИН за касите, поне 6 знака |
| `POINTS_PER_EURO` | `1` | точки за всяко цяло евро |
| `WELCOME_POINTS` | `0` | точки подарък при регистрация |
| `BIRTHDAY_POINTS` | `0` | точки подарък на рождения ден |
| `SCRATCH_MIN_EURO` | `0` | от каква покупка нагоре се дава талон за изтриване |
| `SCRATCH_PRIZES` | няма | какво може да се падне, като „точки:тежест“, например `5:55,10:30,20:12,50:3`; празно = няма талони |
| `CARD_PREFIX` | `29` | първите две цифри на кода на клиента (20–29) |
| `KASA` | `demo` | `demo` или `yanak` |
| `SMS_PROVIDER` | `demo` | доставчик на SMS; засега има само демо |
| `CORS_ORIGIN` | няма | само ако приложението се отваря от друг адрес |
| `TRUST_PROXY` | няма | `1`, когато сървърът е зад nginx |


### Проверка от край до край

Минава през всички раздели: вход, оферти, покупка на касата, точки, награда, история, магазини, новини със снимка, профил, работа без интернет, управление. Нужен е Playwright.

```
npm run build
rm -rf server/data && npm run demo                                  # чиста демо база
node tools/e2e.cjs /папка/за/снимките /някоя/снимка.jpg
```

## Сървърът за клуба

Сървърът на клуба е отделна машина. Примерна услуга има в `deploy/klub.service`: базата и снимките стоят в `/var/lib/klub`, настройките в `/etc/klub/klub.env`. Пред него се слага nginx с HTTPS. При обновяване: `git pull`, `npm ci` в двете папки, `node tools/build-web.mjs`, рестарт на услугата. По-стара база се довежда до новия вид сама при пускане.
